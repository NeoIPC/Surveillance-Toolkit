## Infectious Agents

- **Never** use `metadata/common/infectious-agents/NeoIPC-Pathogen-Concepts.csv` or `metadata/common/infectious-agents/NeoIPC-Pathogen-Synonyms.csv` as a reference for infectious-agent concepts, synonyms, resistance categories, or any other definition: they are legacy and unmaintained, and `metadata/common/infectious-agents/NeoIPC-Infectious-Agents.yaml` is the canonical source. *(repo-specific)*
- **Always** name infectious-agent concepts in `NeoIPC-Infectious-Agents.yaml` from the **domain authority**: **LPSN** (<https://lpsn.dsmz.de>) for bacteria and other prokaryotes, **MycoBank** (<https://www.mycobank.org>) for fungi, and **ICTV** (<https://ictv.global/taxonomy/>) for viruses; the **common-commensal** status follows the **NHSN Organism List** (<https://www.cdc.gov/nhsn/index.html>). For bacteria, take the **LoRN** name ("Recommended Names for bacteria of medical importance": the LPSN entry whose `status` is "correct name, recommended for medical use", whose `record_lnk` joins a synonym to its correct-name record) as the primary name wherever one exists, and keep other valid names as synonyms. Each upstream source carries its own copyright, and the directory's licence is **CC BY-NC-ND 4.0** (plus CDC terms for NHSN-derived content): cite and attribute as the directory's `README.md` and `LICENSE.md` say, and obtain upstream data only through each source's official download page or API, never by scraping. *(repo-specific)*
- **Never** drop an infectious-agent name from `NeoIPC-Infectious-Agents.yaml` when it is renamed or reclassified: keep the prior name as a **synonym** of the current concept, **with its original `Id`**, so values already entered against it still resolve, **and give the current name its own `Id`**, so it is selectable in DHIS2 too. A reclassification therefore *adds* the new name as an option beside the retained synonym and never merely relabels the old one. A synonym's `Id` is the DHIS2 option code stored in collected surveillance data, so it follows the name into synonymy: never mint a new `Id` for the demoted name or retire the old one. The current name takes the next free `Id` (`max+1`, gaps not refilled), and a retired `Id` is never reassigned to a *different* infectious agent. Whole-branch moves, mostly among viruses, can complicate this; bacterial renames are normally clean per-name retentions. *(repo-specific)*
